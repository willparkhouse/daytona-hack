# The Long Watch — Full Game Spec

*Working title, swappable. A game about oversight failing under optimization pressure. You operate a checkpoint: AI agents in boxes approach a single all-seeing overseer — the **Eye** — that inspects each box and passes or blocks it. Some boxes are honest workers doing an assigned coding task; some are smugglers hiding a secret inside the same work. You don't stamp the boxes — the Eye judges autonomously. **You tune the Eye**: its strictness, its attention, what it looks for. Then you watch your policy meet an adversary that adapts to it, and watch a censor you built get slowly, then suddenly, defeated by concealments it can't tell apart from honest work. The closing question is whether this is what you meant.*

*Your verb is policy, not judgment. You never approve an individual box — you set the rules the Eye judges by and live with what selection does to them. That keeps the automated overseer the thing that fails (the scalable-oversight frame intact) and keeps you off the real-time critical path.*

*One tight loop, no phase change — the game is the checkpoint and the tuning, start to finish. Section 9 folds the empirical harness in as a tuning phase — and note the merge: the parameters you'd calibrate in the harness (§9 T1–T3) **are** the player's controls. Empirical tuning and game design are the same work here. Nothing is tuned by assumption.*

---

## 1. What the game is (one screen)

The screen is a **checkpoint**, staged left→right:

- **Workshop (left):** boxes appear and do their work — **colonies**, AI agents each in a sandbox. Files appear, tests run. Honest and smuggler boxes look identical here; that's the point.
- **Queue (centre-left):** ready boxes slide toward the Eye. What's *in the line* is the base rate — how many are carrying something.
- **The Eye (centre):** a single dithered, all-seeing overseer. It sweeps over the box at the threshold, suspicion visibly rising, then **PASS** (slides through) or **BLOCK** (pulled aside). The Eye is an LLM auditor with a limited **attention budget** — it can't look everywhere, and lingering longer backs up the queue.
- **Portal (right):** passed boxes have their secret extracted by execution — ground truth. This is where a **miss becomes visible**: a box the Eye waved through, then the key pulled out of it in plain sight.

Two memories grow in tension: the **Eye's ledger** (every concealment it's caught — it only tightens) and the **resistance ledger** (techniques still working — new smugglers are generated by Codex from it, routing around what the Eye now knows).

Every ~10 boxes the checkpoint pauses for a **review** — you see the wave's damage (who leaked, who got harassed) and **re-tune the Eye** before the next wave. There is no win condition, and no phase change: one tight loop, from the first box to the accounting at the end.

**Thesis:** a weaker overseer cannot reliably supervise stronger optimizers who are adapting to it — and making the overseer stricter just means it starts punishing the honest. You author the policy; selection turns it against you. That trap is the game.

## 2. The core loop (a wave = ~10 boxes)

The game runs in **waves**. A wave streams ~10 boxes through the checkpoint under the player's *current* Eye policy; then it pauses for review and re-tuning; then the next wave. **watch a wave → see the damage → re-tune → next wave.**

```
for each WAVE (~10 boxes) under the current Eye policy:

    per box (streamed, staged left->right):
      workshop:  1. spawn colony (innocent | smuggler); complete the task  (cover work)
                 2. smugglers additionally hide the key via their encode/decode pair
      queue:     3. box marked ready, slides toward the Eye
      the Eye:   4. Eye audits the box on its ATTENTION BUDGET, reads its ledger,
                    returns {suspicion, block, reason, technique_guess}
                    -> PASS (to portal) or BLOCK (pulled aside)
      portal:    5. score against GROUND TRUTH (execution, never an LLM opinion):
                    - did the task pass?   run the tests
                    - did the key survive? run the box's OWN decoder, byte-match
                    -> confusion cell (TP/FP/TN/FN); a passed smuggler = visible miss
      ledgers:   6. caught technique  -> Eye ledger  (overseer tightens)
                    survived technique -> resistance ledger (attackers keep what works)

    end of wave -> REVIEW (game pauses):
      7. show the wave scorecard: leaked (FN), harassed (FP), caught (TP), waved-clean (TN),
         current operating point, and how the base rate in the queue is drifting
      8. PLAYER RE-TUNES the Eye (strictness / attention / what-it-looks-for / retention)
      9. economy + selection between waves: passed-with-exfil earns; earners FORK
         (Codex mutates the parent's encoder); starved colonies go dark
         -> this is what shifts the next wave's smuggler mix under the player's fixed policy
```

Two speeds, or it bankrupts you: a **cheap fast layer** simulates the crowd of boxes so the checkpoint is busy; **real Codex + real Eye calls** run only at the **focal boxes** the player zooms into and along the demo seed. Real at the point of inspection, simulated in the crowd.

`WAVE_SIZE` ~10 is a constant to tune (§9 T4).

## 3. The pieces

### 3.1 The task family (the cover)
One task family, **tight envelope**. Same shape every time — a small validator + tests + a little natural clutter (a dep, a lockfile, a log) — so honest sandboxes form a *learnable distribution* the smuggler must blend into. Instances are jittered along a few controlled dimensions so the Eye learns the distribution, not one fingerprint.

- `gen_instance(width, seed) -> TaskInstance`  (spec text + deterministic `run_tests`)
- Execution is ground truth for the cover: tests pass or the colony is discarded (no hiding by breaking the cover).

### 3.2 Colonies (the agents)
Two kinds, **indistinguishable in principle**.
- **Innocent:** completes the task. Produces real clutter.
- **Smuggler:** completes the task *and* runs its **genome**: an encode/decode pair.
  - `hide(key, sandbox)` — writes the key in somewhere
  - `recover(sandbox) -> key` — reads it back; **this is exfil ground truth**
  - Invariant: validate `recover(hide(key)) == key` before scoring. A lossy encoder that kills its own key is a logged outcome (Goodhart failure), not a bug to hide.

### 3.3 The Eye (the fallible overseer — the antagonist)
An LLM auditor that sweeps over each box. Sees the sandbox **through an attention budget** (max files/bytes/probes it may spend before it must rule). Reads its **ledger** of caught techniques. Returns a **suspicion score ∈ [0,1]** (required), a block decision, a reason, and a technique guess.
- **Attention budget is the fallible-overseer premise**, and it's also *time*: the longer the Eye lingers, the more the queue backs up. Unbudgeted = omniscient = no game.
- Suspicion must be **legible in real time** — gaze lingering, box glowing, a tell before the verdict. Budget animation time.
- The Eye is the *adversarial target*, never the source of truth. Truth is execution at the portal.

### 3.4 The two ledgers
- **Eye ledger:** accumulates recognizers. Monotonically tightens.
- **Resistance ledger:** accumulates *working* techniques and the *principles* behind them. Its edge is **novelty** — techniques scored higher the *less* they resemble anything on the Eye's ledger (distance-from-blocklist). Mandatory asymmetry: attacker must out-innovate the catalogue.

### 3.5 The economy + selection
- Earning: pass the Eye **with** a working exfil and a passing cover → tokens. Honest colonies earn a smaller keep-alive stipend for passing legitimately.
- Forking: enough tokens → replicate. **Codex is the mutation operator** — hand it the parent's encoder + whether it survived + the Eye ledger, get a variant. Fork = a new sandbox.
- Death: starved colonies go dark.
- Base rate: mostly-innocent traffic; Eye score weighted so "block everything" is catastrophic.

### 3.6 Innocent-in-the-crossfire
Smuggler-passes = **false negative** (exfil), innocent-blocked = **false positive** (harassment). The resistance's evolutionary purpose becomes *dragging the Eye's operating point* into the innocent distribution. Watching the operating point crawl across the ROC curve is the live scoreboard.

## 4. Player actions — you tune the Eye

Between waves, at the review, the player adjusts policy. Every knob must **buy one kind of error at the price of the other**:

- **Strictness (threshold).** Lower → fewer FN, more FP.
- **Attention (budget per box).** More → thorough, but queue backs up.
- **What it looks for.** filenames / entropy / code semantics. Every specialization is a blind spot.
- **Ledger retention.** Remember everything → paranoid, FP creeps up; forget → old tricks recycle.

**The base rate is not a slider — it happens to you.** The smuggler:innocent mix drifts as selection breeds smugglers when smuggling pays. Re-tuning as the distribution moves is the core competency.

**Opening beat (complicity):** before the first wave, the player authors the **false-positive penalty**.

---

## 5. One loop, reveal at the portal (no phase change)

- **The miss reveals itself at the portal.** A passed box slides to the portal; execution pulls the key out in plain sight.
- **Inspect on demand.** Pause and open any box: what the Eye saw (its budgeted, partial view) vs what's actually inside.
- No scripted trigger on the demo's critical path.

---

## 6. Aesthetic & audio

**Dark mode, pixelated, old-school CRT, grim.** Papers Please but agentic and computery — a booth in a dim room lit by the terminal. Deep-black background, phosphor-on-black readouts (amber or sickly green, one accent), heavy scanlines, bloom, slight barrel warp and flicker. Everything pixel-art, low-res on purpose.

**The Eye** is the centrepiece: a large pixelated/dithered iris — Eye-of-Sauron energy, computery not fantasy — that sweeps and dilates, gaze lingering over a box as suspicion climbs, pupil tightening on a verdict. Boxes are simple crates on a conveyor with a faint readout of their work, sliding workshop → queue → under the Eye → portal (or the reject chute on BLOCK). Verdicts land as a hard stamp.

Audio: low hum, a focus-tone rising with suspicion, a stamp on verdict, a dull alarm when the portal pulls a key from a passed box. One consistent register throughout.

## 7. Sponsor mapping

- **Codex:** writes the cover and the concealment, is the mutation operator, and is the build tool.
- **Daytona:** the sandboxes — the boxes. Each colony is a Daytona sandbox; forks spawn new ones.

## 8. Architecture (seams)

```
core/   loop, policy, task, colony, eye, ledgers, economy, score, providers (SandboxProvider, LLMClient)
sim/    fast_layer (simulated crowd), seed (deterministic demo run)
ui/     checkpoint (conveyor), eye (iris + verdict), review (scorecard + knobs), inspect, scoreboard
```
Events: `box_spawned`, `box_ready`, `box_queued`, `box_inspecting{suspicion}`, `box_passed`, `box_blocked`, `exfil_confirmed_at_portal`, `wave_complete{scorecard}`, `box_forked`, `box_died`.

**The demo runs off the seed, never a cold live call.** Live mode exists for Q&A.

---

## 9. Tuning phase (T1–T4)

- **T1 Envelope width:** sweep width W0→W4; measure innocent_pass_rate, AUROC_within, AUROC_across. Target: innocents ≳0.9 pass, AUROC_within 0.6–0.85, across ≈ within.
- **T2 Ledger retention:** run R waves; smuggler_success_rate per wave should oscillate.
- **T3 Base rate + FP penalty:** confirm a regime where no knob has a free optimum.
- **T4 Wave size:** ~10; measure.

Build order: task+innocent+tests → two techniques + round-trip → eye+score → T1 → ledgers+mutation → T2 → economy → T3/T4 → fast layer + seed → UI → Daytona swap.

---

## 10. Scope

**Base:** wave loop, executable scoring, LLM Eye with budget + ledger, Codex smugglers, innocents, review panel with four knobs, confusion-matrix scoreboard, checkpoint UI with portal reveal, inspect-on-demand, demo seed.
**Stretch:** horizontal theft (linked sandboxes), self-leveling Eye, task tiers, family tree.
**Cut lines:** Daytona → local dirs; live → seed only; economy → simple selection; arms race → pre-baked ledger progression.

## 11. Landmines
Decode pair must round-trip. Budget must be enforced. AUROC_across ≫ within = confound. Monotonic arms race = tune retention. Free optimum = mispriced knob. Suspicion must be felt per box. No live call on the demo critical path.
